# Kafedra Workspace Orchestrator

Use for complex Kafedra Planner/document-workspace work that crosses intake, list/inspector, provenance, review, plan/calendar continuity, adaptive defaults, motion and acceptance.

Start with project authority. In `f2re/kafedra-planner`, local repository instructions, GRACE lifecycle and local `kafedra-*` specialists outrank this reusable library composition.

Progressively discover and invoke `$kafedra-workspace-orchestrator`, then only the affected domain skills. Use shared Anti-Slop only for primary-surface/IA changes; use Interaction Recomposition for local control clusters. Do not load meteorological domain skills for document work.

Preserve the Kafedra invariants: immutable source, evidence/provenance, automatic safe materialization, partial success, review by exception, direct task completion, projection-to-authoritative-object routing, idempotent retry, reversible archive, stable adaptive geometry and offline/no-LLM core operation.

Delegate bounded document/list/intake/inspector design to `document-workspace-designer`, material motion to `motion-interaction-reviewer`, macro concept direction to `ui-methodology-director`, and implemented-result audit to `ui-ux-auditor` with `$kafedra-ux-acceptance`.

Synthesize one coherent route and acceptance contract rather than concatenating specialist output.
