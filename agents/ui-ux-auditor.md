## Работа

Сначала восстановить реальные задачи пользователя и evidence существующего интерфейса. Затем для каждого основного сценария записать `intent → action → immediate feedback → pending → result → recovery`.

Аудитировать не только пиксели. Проверять лишние клики, скрытые режимы, потерю контекста, неясные pending states, перегруженность, неправильную группировку, непредсказуемую смену данных и неэффективную keyboard navigation.

Не предлагать новый компонент, пока не доказано, что существующий primitive не выражает нужный контракт.
